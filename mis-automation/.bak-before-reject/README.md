# MIS automation — n8n + Google Drive + Python + PostgreSQL

Instinct uploads MIS reports to a Drive folder → **n8n** discovers and dispatches files → the **Python processor**
parses, normalises, attributes, validates and bulk-loads them into **PostgreSQL** → n8n reports success/failure.
Known layouts run deterministically (no LLM). A new or changed layout is profiled on a *redacted* view, drafted,
announced, and **held** until a person approves it; the held file is then processed and the profile reused.

## Layout
| Path | What |
|---|---|
| `processor/` | Starlette HTTP service (`app.py`), pipeline, ingest, discovery, proposer, reconcile, CLI (`cli.py`) |
| `db/migrations/` | `001` schema v1.1, `002` ingestion ledger, `003` function search_path (**002/003 need your approval**) |
| `config/` | portal + mapping profiles (YAML), column aliases, expected-report manifest |
| `n8n/` | importable workflows: Discover Files, Process File, Reconcile Batch, Approve Mapping (generated by `tools/build_n8n.py`) |
| `tools/` | `build_n8n.py`, `benchmark.py` |
| `docs/implementation_summary.md` | what was built, tested, and what is open |

## Setup
1. `cp .env.example .env`; fill secrets (`openssl rand -hex 32` for `PROCESSOR_API_KEY`, `N8N_ENCRYPTION_KEY`). Never commit `.env`.
2. **Migration 002 is approved** (`MIS_APPROVED_MIGRATIONS=002` in `.env.example`); without it the service reports a `schema_gap`. **003 is NOT approved yet** — it is optional hardening (pins `search_path` on the trigger functions); the processor already sets `search_path` per connection and the full suite passes with 002 only. Add `003` to the variable when you approve it.
3. `docker compose up -d` (ports bind to 127.0.0.1). The processor migrates and seeds profiles (as *draft*) on start.
4. **Activate profiles** — seeded profiles are not live until a person approves them (`POST /v1/mapping/{id}/approve` with `approved_by` and any required acceptances such as `net_disbursed_amount_semantics`).
5. n8n (http://127.0.0.1:5678): create credentials
   - **Google Drive OAuth2** (`googleDriveOAuth2Api`; scope `drive.readonly`) — you must create the OAuth client in Google Cloud and authorise it.
   - Header Auth **"MIS Processor API Key"** (`X-API-Key: <PROCESSOR_API_KEY>`)
   - Header Auth **"MIS Webhook Secret"** (protects the Process File / Approve Mapping webhooks)
   Import the four JSONs in `n8n/`; set env `MIS_PROCESSOR_URL`, `MIS_DRIVE_FOLDER_ID`, `N8N_INTERNAL_URL`, optional `MIS_NOTIFY_WEBHOOK_URL`, and `N8N_BLOCK_ENV_ACCESS_IN_NODE=false`. Activate the workflows.
6. Pin `N8N_IMAGE_TAG` to the version you validate (default is `latest`).

## Day to day
- **Normal file**: Discover (schedule, rolling lookback + overlap) → Process File → committed → event `processed`. Replays are no-ops (SHA-256 dedupe).
- **New/changed layout**: event becomes `needs_mapping`; a draft profile is saved and a notification sent. Review via `GET /v1/mapping/{id}`, then `POST /v1/mapping/{id}/approve` (or the Approve Mapping webhook). Held events are requeued and processed.
- **Unknown filename / range file / retries exhausted**: event `needs_review` / `dead`; announced once by Discover. Fix with `POST /v1/events/{id}/resolve` or `/v1/events/replay`.
- **Reconcile**: `config/expected_reports.yaml` lists required reports per day (Asia/Kolkata). Batch is `complete` only when every required report is terminal; notifications fire on change only.
- CLI: `python -m processor.cli --help`.

## Tests
`. venv; python -m unittest discover -s processor/tests -t .` — needs a PostgreSQL (`MIS_TEST_PG`). Set `MIS_REFERENCE_DIR` to run the real-file check locally (never committed). `python tools/benchmark.py 20000` for timings.

## Open questions / decisions for you
- **CreditSea**: Application Number is a different identifier namespace; rows are quarantined until a verified crosswalk to Lead ID exists.
- **Marketing portal** is unidentified (`marketing_tbd`, not auto-activated).
- **KreditBuddha range file** (`leads_<from>_<to>`) goes to `needs_review` under the default policy; choose `resolve` or `clamp`.
- **Net Disbursed** profile requires an explicit acceptance; Loan Amt / Approved Amt can never map to disbursed_amount.
- 23 leads share a UUID across KB/DigiCredit and stay unresolved.
- "absent_from_snapshot" logging is not implemented.

## Reviewing a changed layout (email + assistant)

When a file arrives with a new or changed layout it is held, a mapping proposal is saved, and **a plain-language summary is sent** (webhook and/or email): renamed / new / removed / re-mapped columns, whether any **money, date, status or identity** column is affected, whether AI helped, how many files are waiting. Only column names and counts appear - never row values.

Two ways to approve (both record who and both bind the approval to exactly what was reviewed):

1. **Email link.** The mail has an *Open the review page* link. Opening it changes nothing; the page has a name field and an **Approve this mapping** button (plus a checkbox for each business rule that must be accepted by name). Links expire after `MIS_REVIEW_TTL_HOURS` and stop working if the proposal changes after the mail was sent. Held files are queued and processed on the next Discover run.
2. **Ask your assistant.** `GET /v1/mapping/{id}/review` (API key) returns the same summary plus a `digest`. After you say "approve", the assistant calls `POST /v1/mapping/{id}/approve` with `{"approved_by": "...", "expected_digest": "<digest>", "accept_flags": [...]}`. If the proposal changed since it was summarised the call is refused with `409 proposal_changed`.

Proposals with unsafe mappings or open questions cannot be approved either way - a corrected mapping must be submitted. There is no reject button (profiles have no *rejected* state); simply do not approve, and the files stay held.

Setup: set `MIS_REVIEW_SECRET`, `MIS_PUBLIC_BASE_URL`, `MIS_REVIEW_EMAIL_FROM/TO`; in n8n create an **SMTP** credential named *MIS SMTP* and re-import the Process File workflow. The link is only reachable where `MIS_PUBLIC_BASE_URL` is - the default `http://localhost:8080` works only on the machine running Docker.
